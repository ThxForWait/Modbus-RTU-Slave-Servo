# Modbus-RTU-Slave-Servo

Контроллер сервопривода на Arduino Uno, который работает как **Modbus RTU Slave**. Протокол написан с нуля, без сторонних Modbus-библиотек. Мастер (ПК, ПЛК, SCADA) по последовательному порту задаёт сервоприводу угол и скорость и читает его текущее положение.


## Что делает проект

- Принимает по UART кадры Modbus RTU и отвечает на них как подчинённое устройство (Slave ID = 1).
- Поддерживает функции `0x03` (Read Holding Registers) и `0x06` (Write Single Register). На остальные функции отвечает исключением `0x01` (Illegal Function), на выход за пределы карты регистров — `0x02` (Illegal Data Address).
- Проверяет CRC-16 каждого входящего кадра. Кадры с неверной CRC молча отбрасываются.
- Поворачивает сервопривод на заданный угол **плавно**, по одному градусу за шаг, с настраиваемой скоростью.
- Не блокирует цикл `loop()`: целевой угол и скорость можно менять прямо во время движения, сервопривод сразу реагирует.

## Как это устроено

Код делится на две независимые части, которые обмениваются данными через общий массив 16-битных регистров `mbRegisters[]`.

| Часть | Файл | Что делает |
|---|---|---|
| Modbus RTU Slave | `src/ModbusSlave.h`, `src/ModbusSlave.cpp` | Принимает байты, собирает кадр, проверяет CRC, обрабатывает `0x03`/`0x06`, формирует ответ |
| Управление сервоприводом | `src/sketch.ino` | Функция `updateServo()` читает регистры и двигает вал |

**Приём кадра** (`poll()`). Байты из `Serial` копятся в буфере (64 байта). Конец кадра определяется по паузе: если после последнего байта прошло больше 10 мс (для 9600 бод), кадр считается завершённым и передаётся в `processFrame()`. Там проверяются адрес Slave и CRC-16, затем кадр разбирается по коду функции.

**Движение сервопривода** (`updateServo()`). Целевой угол ограничивается диапазоном 0–180°. Если с прошлого шага прошло не меньше `speedDelay` мс, текущий угол меняется на 1° в сторону цели, вызывается `Servo.write()`, а текущий угол записывается обратно в регистр статуса. `delay()` не используется, поэтому Modbus опрашивается непрерывно.

### Карта регистров

| Адрес (hex) | Modbus-адрес | Назначение | Доступ | Значение по умолчанию |
|---|---|---|---|---|
| `0x0000` | 40001 | Целевой угол, 0–180° | чтение/запись | 90 |
| `0x0001` | 40002 | Задержка между шагами, мс на 1° (больше — медленнее, `0` — мгновенный поворот) | чтение/запись | 15 |
| `0x0002` | 40003 | Текущий угол | только чтение | 90 |

> Регистр `0x0002` формально можно записать по Modbus, но прошивка перезапишет его при следующем шаге, так что смысла в этом нет.

### Параметры связи

| Параметр | Значение |
|---|---|
| Slave ID | 1 |
| Скорость | 9600 бод |
| Формат | 8 бит данных, без чётности, 1 стоп-бит (8N1) |

Параметры задаются в начале `src/sketch.ino` (`SLAVE_ID`, `BAUD_RATE`, `SERVO_PIN`).

### Схема подключения

Сервопривод:

| Провод сервопривода | Пин Arduino Uno |
|---|---|
| Сигнал (PWM, оранжевый) | D9 |
| Питание (красный) | 5V |
| Земля (коричневый) | GND |

Если запускать на реальной плате через USB-UART-адаптер:

| Пин Arduino | Пин USB-UART |
|---|---|
| D1 (TX) | RXD |
| D0 (RX) | TXD |
| GND | GND |

## Как запустить (симулятор Wokwi + виртуальный COM-порт)

Физическая плата не нужна: Arduino и сервопривод эмулирует [Wokwi](https://wokwi.com), а мастера и Arduino связывает пара виртуальных COM-портов.

### Что понадобится

- Windows
- Virtual Serial Port Tool — создаёт пару связанных виртуальных COM-портов
- QModBus — Modbus-мастер для отправки запросов
- Браузер с поддержкой Web Serial (Chrome или Edge), чтобы Wokwi мог открыть COM-порт

### Шаги

1. **Создайте виртуальную пару портов.** В Virtual Serial Port Tool создайте локальный мост (например, `COM1` ↔ `COM2`). В диспетчере устройств оба порта должны появиться.
2. **Откройте проект в Wokwi.** Создайте на wokwi.com новый проект Arduino Uno и перенесите в него файлы из папки `src/`: `sketch.ino`, `ModbusSlave.h`, `ModbusSlave.cpp`, `diagram.json`, `libraries.txt`. В `diagram.json` уже есть деталь `wokwi-serial-port` (9600 бод), подключённая к пинам `0` и `1` Arduino, а в `libraries.txt` — библиотека `Servo`.
3. **Запустите симуляцию.** Wokwi запросит доступ к последовательному порту — выберите **COM1**. Сервопривод встанет в 90°, скорость по умолчанию 15.
4. **Настройте QModBus.** Выберите режим **Modbus RTU**, отметьте **Active**, порт **COM2** (парный к COM1), скорость **9600**, формат 8N1 (чётность **None**). Slave ID — **1**.
5. **Отправляйте команды** (примеры ниже).

> Подойдут и другие программы для виртуальных COM-пар (например, com0com) и любой другой Modbus-мастер. Главное, чтобы у мастера были те же параметры порта, что и в `sketch.ino`.

## Примеры команд

В QModBus адреса регистров указываются с нуля (поле *Start address*), номер устройства (Slave ID) — 1.

| Действие | Функция | Start address | Данные | Кадр запроса (hex, с CRC) |
|---|---|---|---|---|
| Повернуть вал в 0° | `0x06` | 0 | 0 | `01 06 00 00 00 00 89 CA` |
| Повернуть вал в 180° | `0x06` | 0 | 180 | `01 06 00 00 00 B4 89 BD` |
| Установить скорость 60 мс/шаг | `0x06` | 1 | 60 | `01 06 00 01 00 3C D8 1B` |
| Прочитать все три регистра | `0x03` | 0 | количество: 3 | `01 03 00 00 00 03 05 CB` |

Ответ на чтение при цели 180°, скорости 60 и текущем угле 180°:

```
01 03 06 00 B4 00 3C 00 B4 51 14
```

Пример проверки скорости: запишите в регистр 1 значение 60 (визуально ничего не изменится), затем прочитайте регистры 0–2 и убедитесь, что скорость стала 60. Если запустить поворот с 180° в 0° и в это время читать регистры, значение «Текущий угол» будет меняться.

## Запуск на реальной плате (необязательно)

Код написан на стандартном Arduino API, поэтому его можно загрузить и на настоящую Arduino Uno:

1. В Arduino IDE создайте скетч `sketch` и положите в его папку `sketch.ino`, `ModbusSlave.h` и `ModbusSlave.cpp`. Библиотека `Servo` входит в состав IDE.
2. Подключите сервопривод к D9, 5V и GND.
3. Загрузите прошивку и подключайтесь мастером к COM-порту платы (9600, 8N1, Slave ID 1).

Заметка: `Serial` занят и Modbus-обменом, и USB-загрузкой, поэтому на время прошивки отключайте от D0/D1 внешний USB-UART-адаптер. Отладочный вывод через `Serial.print` использовать нельзя: он испортит Modbus-кадры.

## Ограничения

- Только функции `0x03` и `0x06`. Нет `0x10` (запись нескольких регистров), дискретных входов и катушек.
- Широковещательный адрес `0` не поддерживается: кадры для других адресов игнорируются.
- Размер кадра ограничен 64 байтами, а ответ на `0x03` — 64 байтами, то есть чтение укладывается примерно в 30 регистров. В проекте регистров всего три.
- Конец кадра определяется фиксированной паузой 10 мс, подобранной под 9600 бод. На других скоростях её нужно пересчитать (по стандарту это 3,5 символа).
